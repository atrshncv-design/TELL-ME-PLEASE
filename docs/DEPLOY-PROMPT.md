## КРИТИЧЕСКИЕ ПРАВИЛА (из ошибок прошлого раза — НЕ НАРУШАЙ)

1. **Используй ТОЛЬКО штатный инструмент деплоя платформы** (тот, которым деплой
   делался в прошлый успешный раз). НЕ копируй файлы вручную в `/home/z/my-project/`,
   НЕ правь файлы на сервере напрямую — платформа разворачивает проект из `repo.tar`
   при СТАРТЕ контейнера, и ручные правки наружу не пробрасываются.
2. **НЕ запускай dev-сервер вручную** (`bun run dev`, `next dev` и т.п.) — штатный
   процесс запускается при старте контейнера. Ручной сервер конфликтует и не
   обслуживает внешний трафик (платформа маршрутизирует через свой контрольный сервис
   и Caddy :81).
3. **НЕ создавай временных эндпоинтов** (типа `/api/debug-env`) — ничего не добавляй
   в репозиторий сверх того, что в нём есть. Проверку env делай косвенно: если
   `/api/chat/stream` отвечает на запрос — ключи есть; если «Сервис не настроен» —
   ключей нет.
4. **Платформа кэширует старый билд на уровне ингресса.** Если после деплоя внешний
   URL всё ещё отдаёт старую версию (build ID `fbCNoYyYfmO80Vl1` или главная без карты
   миров) — это НЕ решается ручными правками. Остановись и сообщи пользователю:
   нужно нажать «Restart/Redeploy» в дашборде. Не пытайся чинить сервер руками.
5. **`next dev` (Turbopack) нестабилен на этой платформе** (падает после 1–3 запросов).
   Это известная проблема, не чини её — отметь в отчёте. Если в настройках проекта
   есть поле «команда запуска» — рекомендую production-режим, но менять настройки
   может только пользователь.

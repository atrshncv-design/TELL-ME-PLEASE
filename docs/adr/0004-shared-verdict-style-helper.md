## Контекст

После неверного ответа зелёная галочка появлялась у правильного варианта, и ученики принимали свой провал за успех; паттерн мгновенной проверки выбора повторяется во всех instant-check заданиях, не только в квизе.

## Решение

Визуал вердикта мгновенной проверки описан одним общим хелпером: константы классов (выбранный неверный вариант — крупный красный с ✗, правильный — скромная плашка «Правильный ответ: …» без праздничной анимации награды) и тайминги перехода к следующему вопросу (при неверном ≥1.8 c) живут в одном месте, все instant-check компоненты берут их оттуда.

## Почему

Рассмотрен и отвергнут вариант править каждый компонент по отдельности: дублирующиеся константы неизбежно разъезжаются между заданиями, и та же путаница «зелёненькое — значит правильно» всплыла бы в другом задании. Отвергнут фикс только квиза: требование единообразия прямо распространяет паттерн на все instant-check компоненты, а расхождения между заданиями и так раздражали.

## Последствия

Изменение вердикта теперь по умолчанию меняет все задания разом: точечная кастомизация под конкретное задание потребует параметров хелпера или сознательного выхода компонента из общего паттерна. Тайминги стали общим UX-контрактом — замедлить или ускорить переход в одном задании нельзя, не затронув остальные. Новые instant-check задания обязаны сами узнать о хелпере: его неиспользование нигде не проверяется.

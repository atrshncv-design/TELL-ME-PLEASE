# SPEC: time travel mission — Живой MVP на space.z-ai

_Спецификация фазы 2 (autopilot, to-spec). Синтез grilling-интервью (14 вопросов, 31.07) + преемственность с `docs/SPEC.md` (фаза 1, 5 класс)._

## Состояние на старте (фактическое)

- **Фронт** (`frontend/`, Next.js 16.2.10 + React 19 + Tailwind 4 + Framer Motion): задеплоен на space.z-ai (`m1ed663b3d70-d.space-z.ai`), но **работает как статика без бэкенда** — голосовой чат на проде мёртв.
- **Бэкенд** (`backend/`, FastAPI): LLM-чат (WS `/ws/chat`), SSE, ротация ключей opencode zen, промпт-роутер по ролям, аналитика (`POST /api/event` в SQLite/JSONL), Kokoro TTS (ONNX, Python) — **всё это не переносится на space.z-ai** (нет Python/Docker, WebSocket только через отдельный мини-сервис).
- **Контент**: все классы наполнены — 5 кл: 22 задания (включая серию to-be), 6–9 кл: по 16 заданий. `content/tasks/grade_{5..9}/`.
- **Геймификация** (сделано): карта миров (5 миров, Verb Bot маркер), звёзды, алмазные бейджи, звуки (correct/wrong/fanfare), фразы похвалы Verb Bot по классам.
- **Клиентские хуки** (`frontend/src/lib/`): `useSpeechRecognition` (webkitSpeechRecognition, en-US) — работает на проде без изменений; `useAudioPlayer` (AudioContext.decodeAudioData — WS-аудио, заменяется на speechSynthesis); `useAnalytics`, `useProgress` (localStorage), `useSound`, `useWebSocket`, `useSpeechRecognition`.
- **Стек жив локально**: FastAPI + OpenCode Zen + Kokoro в Docker + `npm run build` зелёный + `tsc --noEmit` 0 ошибок.

## Problem Statement

Платформа задеплоена, контент и геймификация готовы, но **на боевом URL не работает главная фишка — голосовой диалог с ИИ-собеседником**: бэкенд FastAPI/Kokoro физически не может жить на space.z-ai (нет Python/Docker). Плюс по дизайну заказчица хочет ярче и «прикольнее» (дети 5–9): больше цветов, картинок, персонажей, мемов. Учительнице нужна скрытая админ-панель с анонимной статистикой для диссертации. Требование пользователя: **живой работающий MVP под 100 одновременных в пик (реально ≤30, голосовой чат 5–10 одновременных запросов)**.

## Solution

Полностью перевести бэкенд на space.z-ai: **FastAPI → Next.js API Routes** (LLM-чат с SSE вместо WebSocket, ротация ключей in-memory, промпт-роутер, аналитика). Голос: **браузерный speechSynthesis (TTS)** + уже клиентский STT — сервер для голоса не нужен. Ввести **очередь с трейтлимитом** для LLM-запросов с UI-репликой персонажа («Думаю над твоими словами…») — стабильность на пике. Аналитика: незаметная кнопка → модалка логин/пароль → админ-панель с анонимными цифрами. Дизайн: яркая «детская» палитра через DESIGN.md-токены (Tailwind-экспорт), стикеры/эмодзи, стоковые иллюстрации/фото, свои AI-маскоты. Цель — сервис, который не падает при 30 детях и радует глаз.

## User Stories

### Голосовой чат на space.z-ai (приоритет 1)
1. Как ученик, я хочу открыть сайт с телефона и **поговорить с ИИ-собеседником голосом** (говорю — он отвечает голосом), чтобы практиковать английский.
2. Как ученик, я хочу слышать ответ ИИ **голосом через динамик телефона** (speechSynthesis), без установки чего-либо.
3. Как ученик в браузере без голосового движка (редкий Android), я хочу **видеть текст ответа**, а не тишину — текстовый фолбэк.
4. Как ученик, я хочу, чтобы микрофон **сам включался после реплики ИИ** и диалог шёл непрерывно (как сейчас в STT-хуке).
5. Как ученик, я хочу, чтобы **ИИ держал роль** (Гарри Поттер, сверстник, «расскажи о себе») согласно заданию — промпты по task_id.
6. Как ученик, я хочу, чтобы через **3 минуты** диалог завершался экраном фидбека (поведение из фазы 1 сохраняется).
7. Как ученик в Firefox, я хочу **текстовый ввод реплик** вместо микрофона (существующий фолбэк сохраняется).

### Очередь и стабильность на пике (приоритет 1)
8. Как ученик при пике (класс 30 чел.), я хочу, чтобы мой запрос **встал в очередь**, а персонаж сказал «Думаю над твоими словами…» текстом на экране — чтобы сервис не падал.
9. Как ученик при одиночном использовании, я хочу **мгновенный ответ** без очереди (очередь невидима, когда свободно).
10. Как администратор, я хочу, чтобы система **держала 5–10 одновременных LLM-запросов** стабильно, а при переполнении — мягко извинялась, а не выдавала ошибку.
11. Как администратор, я хочу **ротацию ключей по лимиту** (in-memory, без cron) — несколько ключей в `.env`, переключение при rate-limit.

### Аналитика и админ-панель (приоритет 2)
12. Как учитель, я хочу **незаметную кнопку** входа (ученики её не замечают) → модалку с логином и паролем → админ-панель.
13. Как учитель, я хочу видеть **анонимную статистику**: сколько детей зашло, какие классы/задания проходили, сколько дошли до голосового чата, средние баллы — для диссертации.
14. Как администратор, я хочу, чтобы **пароль хранился только в `.env`** (`ADMIN_PASSWORD`), а не в коде и не в БД.

### Дизайн и геймификация (приоритет 2)
15. Как заказчица, я хочу **яркую цветную палитру** (дети 5–9), единую на всей платформе, с проверкой контраста (WCAG AA).
16. Как ученик, я хочу видеть **стикеры, эмодзи, картинки и персонажей** в интерфейсе — весёлый визуал на карте миров, карточках, в Verb Bot.
17. Как заказчица, я хочу **своего маскота-персонажа** (уникальный, без правовых рисков), который станет лицом платформы.
18. Как ученик, я хочу, чтобы **Verb Bot и карта миров** стали ярче и живее (обновление существующего, не переделка).

### Инфраструктура и деплой (приоритет 3)
19. Как администратор, я хочу, чтобы платформа работала в **production-режиме** на space.z-ai (не `next dev`), если платформа позволяет — под нагрузкой важна скорость.
20. Как администратор, я хочу, чтобы **весь функционал был на одном URL** — фронт + API + SSE + аналитика, без внешних сервисов.
21. Как администратор, я хочу, чтобы **неиспользуемые артефакты** (huggingface/, backend/ Kokoro-часть) были убраны или помечены устаревшими — чтобы не путать.

## Implementation Decisions

### Голосовой тракт на space.z-ai
1. **Бэкенд переезжает в Next.js API Routes** (`frontend/src/app/api/…`): `POST /api/chat/stream` (SSE-стриминг через `ReadableStream` + `text/event-stream`, как уже проверено агентом z.ai), `POST /api/event` (аналитика), `GET /api/admin/stats` (админ-панель). Логика переносится 1:1 из `backend/app/main.py` (LLM-вызов, стриминг токенов, ветки `final_feedback`/`_session_timer`).
2. **WebSocket не используется** — POST + SSE достаточно для диалога ребёнок→ИИ→ребёнок (полный дуплекс не нужен). `useWebSocket.ts` заменяется SSE-клиентом (`fetch` + `ReadableStream` парсинг).
3. **Ротация ключей in-memory**: `LLM_API_KEYS` (разделитель — как в `key_rotation.py`), переключение при ошибке лимита (429/пустой content). Cron не нужен — срабатывание по событию.
4. **Модели**: `LLM_MODELS` в `.env` (порядок перебора). Сейчас — deepseek v4 flash free (проверить актуальный список `opencode.ai/zen/v1/models` при переносе; фаза 1 использовала `ling-3.0-flash-free` → `nemotron-3-ultra-free` как fallback).
5. **Промпт-роутер**: `prompts_config.json` переносится без изменений (роли по task_id → fallback grade_N; запрет динамической генерации промптов — правило `CLAUDE.md:12`).
6. **TTS = браузерный `speechSynthesis`**: хук `useSpeechSynthesis` — выбор лучшего en-US голоса (приоритет: Google UK English Male/Female → Microsoft → Siri), кэш голосов (`voiceschanged`), `rate` ≈ 1.0. Заменяет `useAudioPlayer` + Kokoro.
7. **Текстовый фолбэк** (нет голоса/браузер без поддержки): ответ ИИ всегда показывается текстом на экране; звук — progressive enhancement.
8. **STT без изменений**: `useSpeechRecognition` уже клиентский и работает на проде.

### Очередь и стабильность
9. **FIFO-очередь + трейтлимит** в памяти процесса: максимум **N=8 одновременных LLM-запросов** (5–10 — целевой диапазон), остальные ждут в очереди (таймаут ожидания ~30с).
10. **UI-реплика ожидания**: пока запрос в очереди, персонаж/бот показывает текстом «Думаю над твоими словами…» (с анимацией «печатает»), голосом не озвучивается.
11. **Мягкое падение**: таймаут LLM / все ключи исчерпаны → извиняющаяся реплика персонажа («Мне нужно на минутку отдохнуть…») + предложение повторить, никогда — голый `error`/пустой экран.
12. **Одиночный режим без задержек**: очередь невидима при свободных слотах (таймаут ожидания = 0 при свободном слоте).

### Аналитика и админ-панель
13. **`POST /api/event` → JSONL-файл** (`data/events.jsonl`, fs на space.z-ai работает). События воронки из фазы 1: `grade_selected`, `section_selected`, `task_started`, `task_completed(+score)`, `task_abandoned`, `voice_session_started`, `voice_session_ended`. Анонимный device-session ID из localStorage.
14. **Вход админа**: незаметная кнопка (мелкая, в футере или в углу карты миров — без надписи «админ») → модалка с логином+паролем → проверка против `ADMIN_PASSWORD` из `.env` (логин — константа, например `admin`; пароль — только env). Сессия — `sessionStorage`/cookie, короткий срок.
15. **Админ-панель**: `/admin` (закрытый роут, server-side проверка) — простой дашборд: счётчики посещений, классы, задания, доходимость до голосового чата, средние баллы, последние N событий. Минималистичный UI, без графиков-тяжеловесов (таблица + цифры).

### Дизайн
16. **`DESIGN.md` в корне проекта** (скилл design-md): яркая детская палитра (основной + 4 акцента по категориям секций — уже есть цветовая кодировка), токены, экспорт в Tailwind v4 theme. Линт: `npx -y @google/design.md lint` + WCAG AA.
17. **Стикеры/эмодзи**: Twemoji/OpenMoji — наборы бесплатных стикеров (лицензии свободные) — на карте миров, карточках заданий, в Verb Bot-репликах.
18. **Стоковые иллюстрации/фото**: Pexels/Unsplash (фото, свободные лицензии) для фонов; Open Peeps/Blush (иллюстрации-человечки, настраиваемые по цвету) для персонажей-помощников.
19. **AI-маскоты**: 1–2 уникальных персонажа (не из мультиков — права) в фирменных цветах: обновлённый Verb Bot + маскот карты миров. Генерация — через open-design (BYOK) или бесплатный API; детали в тикете.
20. **Права**: конкретных персонажей Диснея/кино не используем; стиль «в духе мультиков» — можно. Заказчице — объяснить одной фразой.

### Инфраструктура
21. **Production-режим на платформе**: проверить, можно ли переключить space.z-ai с `next dev` на `next build && next start` (`.zscripts`/конфиг платформы). Если нет — принять dev-режим и компенсировать очередью.
22. **Уборка**: `huggingface/` — удалить или пометить `DEPRECATED.md`; `backend/` — после переноса всей логики пометить «историческая реализация» (не удалять без явного согласия — там бенчмарки и промпты-первоисточники); `docs/HF_DEPLOY.md` — пометить устаревшим.
23. **Env-переменные** (имена; значения — только пользователь в `.env`): `LLM_API_KEYS`, `LLM_MODELS`, `ADMIN_PASSWORD`, `ADMIN_LOGIN` (опц.), `NEXT_PUBLIC_WS_URL` (удалить — WS нет).

## Testing Decisions

- **Внешнее поведение, не детали** (инвариант фазы 1): чеки = `npx tsc --noEmit` 0 ошибок + `npm run build` зелёный + `scripts/verify-content.mjs` ALL PASSED.
- **Голосовой end-to-end на проде**: после тикетов голосового тракта — живой прогон на `m1ed663b3d70-d.space-z.ai`: открыть голосовое задание с телефона/эмулятора iPhone и Android, сказать реплику → услышать ответ (speechSynthesis), замерить TTFB.
- **Нагрузочный тест очереди**: эмуляция 10 одновременных SSE-запросов (скрипт `scripts/load-test.mjs`) — проверить, что 8 в обработке, 2 в очереди с репликой «Думаю…», ни одного 500, время ответа ≤ N сек.
- **SSE-парсинг**: unit-прогон клиента SSE на мок-стриме (контракт: `init` → `user` → токены → `done`/`error`).
- **Админ-панель**: вход с правильным/неправильным паролем, пустой дашборд до событий, цифры после прогона событий.
- **Дизайн**: `npx -y @google/design.md lint DESIGN.md` без ошибок; визуальный аудит 5 скринов (карта миров, класс, секции, задание, голосовой чат) на мобильном разрешении.
- **Правки заказчицы по контенту** (она прислала пару правок): применить и прогнать verify-content.

## Out of Scope

- **Полный кабинет учителя** (вариант C: разбор ошибок, экспорт, личные кабинеты учеников) — выбран вариант B.
- **Авторизация учеников, аккаунты, скоринг между устройствами** — прогресс остаётся в localStorage.
- **Английская версия UI** — интерфейс русский (решение фазы 1, не пересматривалось).
- **Персонажи из конкретных мультиков/фильмов** (права) — только стиль «в духе» и свои маскоты.
- **Контент 6–9 классов** — уже наполнен, доработка только по правкам заказчицы.
- **HF Spaces / Render / внешний Kokoro-микросервис** — отвергнуты пользователем.
- **Video/AudioWorklet оптимизации**, **cron-ротация** (платформа не поддерживает; in-memory достаточно).

## Further Notes

- **Правила проекта** (`CLAUDE.md`): запрет server-side STT, запрет динамической генерации промптов, запрет утечки ключей, обязательный streaming pipeline.
- **Ключи**: пользователь кладёт значения в `.env` сам (локально и на space.z-ai). В коде — только имена переменных. Сейчас есть 1 ключ opencode zen, остальные добавятся.
- **Устройства**: личные смартфоны детей (iOS/Android, современные). Голоса speechSynthesis на них качественные (Siri/Google).
- **Нагрузка**: потолок 30 детей одновременно (учительница контролирует), целевые 5–10 одновременных LLM-запросов.
- **Защита диссертации — не драйвер** (решение пользователя): приоритет — работающий сервис.
- **Graphify** (`~/.graphify-venv`): скилл установлен в Hermes; полный прогон графа проекта — после завершения этапа (чтобы граф отражал финальную структуру).

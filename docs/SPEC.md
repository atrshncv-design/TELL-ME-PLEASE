## Problem Statement

Интерактивная платформа для изучения английского детьми 5–9 классов. Контент 5 класса готов, бэкенд и стриминг работают. Но: голосовой AI «мёртв» из-за reasoning-модели (исправлено в T1), одно задание рендерится неправильной механикой, кросс-браузерность голоса отсутствует, роли AI не закреплены, прогресс не сохраняется, нет аналитики для учителя. Ученик не может ни полноценно поговорить с AI-аватаром, ни увидеть свой прогресс; учитель не видит, как дети пользуются платформой.

## Solution

Довести 5 класс до рабочего MVP: рабочие голосовые задания со строгими ролями и 3-мин финалом, корректные механики всех 16 заданий, кросс-браузерный голос с текстовым фолбэком, клиентский прогресс, фундамент аналитики воронки, цветовая навигация, адаптив для смартфонов. Конвертация контента 6–9 классов, UI дашборда аналитики и полный редизайн — следующие фазы.

## User Stories

### Рендер и механики заданий
1. Как ученик 5 класса, я хочу кликнуть на любое из 16 заданий и увидеть правильную интерактивную механику, чтобы не путаться.
2. Как ученик, я хочу в «Наречия: построй» собирать предложения кликами по банку слов (наречие + время + глагол), а не видеть пустые пропуски.
3. Как ученик, я хочу, чтобы навигация (секции, задания) соответствовала контенту — все 16 доступны, ни одного тупика.

### Голосовой тракт
4. Как ученик, я хочу нажать микрофон и услышать ответ AI за 1–3 секунды, чтобы диалог шёл живо.
5. Как ученик, я хочу, чтобы микрофон ожил после реплики AI, чтобы продолжить без перезагрузки.
6. Как ученик, я хочу в «Интервью с Гарри Поттером», чтобы AI держал роль Гарри, а не отвечал как абстрактный бот.
7. Как ученик, я хочу, чтобы через 3 минуты AI попрощался и дал обратную связь по ошибкам.
8. Как ученик в Firefox, я хочу, чтобы голосовое задание не было полностью недоступно — чтобы работал текстовый ввод реплик.

### Прогресс и навигация
9. Как ученик, я хочу видеть бейджи «✓ 8/10» на пройденных заданиях и счётчик «Пройдено 5/16», чтобы чувствовать прогресс.
10. Как ученик, я хочу видеть только классы с реальным контентом, чтобы не попадать в тупик «не удалось загрузить».
11. Как ученик, я хочу цветовую кодировку секций (грамматика/словарь/аудирование/общение), чтобы визуально ориентироваться.

### Аналитика (фундамент)
12. Как учитель, я хочу, чтобы платформа анонимно фиксировала шаги учеников по воронке (выбор класса → раздел → задание → результат), чтобы понять, где дети застревают и какие задания популярны.
13. Как учитель, я хочу иметь отдельный защищённый вход в дашборд (следующая фаза), скрытый от детей.

### Адаптив и деплой
14. Как ученик, я хочу открывать платформу с телефона (через QR) и видеть рабочий UI без зума, с доступным микрофоном.
15. Как учитель, я хочу задеплоить платформу и получить рабочий HTTPS-URL для QR-кода.

## Implementation Decisions

### Голосовой тракт (бэкенд)
1. **Модель** (T1 — сделано): `ling-3.0-flash-free` основная. Не-reasoning, TTFB 1.5с.
2. **Fallback на модель** (T2): при пустом/ошибочном `content` от ling — повторить на `nemotron-3-ultra-free`. Не путать с ротацией ключей. Список моделей — `LLM_MODELS=ling-3.0-flash-free,nemotron-3-ultra-free` в `.env`, читается бэкендом.
3. **Защита от пустого content** (T3): при пустом `full_reply` после fallback — отправить клиенту `{"type":"error","content":"..."}` вместо пустого `done`.
4. **Роли по заданиям** (T10): расширить `prompts_config.json` ключами `harry_potter_interview`, `peer_conversation`, `about_yourself`. `prompt_router.resolve_prompt` сначала ищет по `task_id`, потом падает на `grade_N`. Жёсткий хардкод ролей (соответствует запрету `CLAUDE.md:12`).
5. **3-мин финал** (T11): проверить срабатывание `_session_timer` + ветки `final_feedback` в `main.py:175-191`; фронт показывает экран завершения.
6. **Аналитика-эндпоинт** (T16): `POST /api/event` — параметризованная запись событий воронки в SQLite/JSONL. События: `grade_selected`, `section_selected`, `task_started`, `task_completed`(+score), `task_abandoned`, `voice_session_started`, `voice_session_ended`. Анонимный device-session ID (генерируется на фронте, без логина). Защита от SQL-инъекций — параметризованные запросы по построению. UI дашборда — следующая фаза.
7. **Вход админа** (T17): HTTP Basic Auth на роуте `/admin/*`, пароль в `.env` (`ADMIN_PASSWORD`). Пароль НЕ в БД → SQL-инъекция невозможна по построению. Дети не видят вход (нет ссылки в UI).

### Голосовой тракт (фронтенд)
8. **Удалить /chat** (T-new): удалить `frontend/src/app/chat/page.tsx`. Единственный голосовой экран — `VoiceChatTask`.
9. **Гонка STT** (T4): `useSpeechRecognition.ts` — guard «уже запущен» в `onend` (не глотать `InvalidStateError` молча); восстановление после TTS опирается на надёжный флаг состояния, не на `wasListeningRef`.
10. **Кросс-браузерный фолбэк** (T6): при `supported=false` (Firefox) — явный баннер «Голос работает в Chrome/Edge» + текстовый ввод реплик как запасной канал. Снимает ощущение «мёртвой кнопки».
11. **Визуальные состояния микрофона** (T7): чёткая индикация `!connected` (серый + тултип «ожидание соединения»), `muted` (бейдж 🔇), `listening` (пульсация). Убрать двусмысленность «кнопка есть, но не реагирует».
12. **События аналитики на фронте** (T16-фронт): хук `useAnalytics`, шлёт события воронки на `POST /api/event` с device-session ID из localStorage.

### Задания
13. **BuildSentenceTask** (T8 — новый компонент): для типа `build-sentence`. Механика по `Content_Mechanics.md:36-38`: банк слов (`adverbs[]` + `time_phrases[]` + `base_verb` + `subject` из JSON), клики собирают предложение в строку, кнопка «Проверить», Framer Motion (`layout` + `AnimatePresence`). Валидация порядка: `subject + adverb + base_verb + time_phrase` (напр. "I always play games every day"). Case в `TaskRenderer.tsx`. Отменяет RFL-30.

### Прогресс
14. **localStorage-прогресс** (T-new): хук `useProgress` сохраняет по `taskId` факт прохождения + балл. `sections/page.tsx` (после T9) показывает бейджи на карточках + счётчик «Пройдено N/16» сверху. `onComplete` из компонентов наконец подключается. Без бэкенда, без регистрации.

### Навигация и UI
15. **Динамические классы** (T-new): `class/page.tsx` показывает только классы с реальным контентом (сканирует `public/content/tasks/grade_*/index.json`). Сейчас — только 5.
16. **Цветовая кодировка секций** (T-new): 4 категории получают акцентные цвета карточек (grammar=индиговый, vocabulary=изумрудный, listening=янтарный, speaking=розовый). Минимальная правка CSS-классов.
17. **Mobile-first** (T-final-1): viewport meta в `layout.tsx` + `100dvh`/`min-h-0` для голосового экрана + аудит всех заданий в мобильном разрешении. Отдельный финальный тикет.

### Тестирование и верификация
18. **Без тест-фреймворка** (инвариант): чеки на тикет = `tsc --noEmit` 0 ошибок + `npm run build` зелёный + `verify-content` ALL PASSED + браузерный скриншот (через `web-gui-tester` skill) + WS-прогон с замером TTFB для голоса.
19. **Sanity-чеки чистых функций** (T12): расширить `verify-content.mjs` проверками `serializeContext` (роль Гарри для интервью) и `normalize` (консистентность по 16 файлам).

## Testing Decisions

- **Внешнее поведение, не детали.** Тестируем через браузер (`web-gui-tester`): рендер, клик, голосовой цикл. Не assert-им внутренние стейты React.
- **Voice end-to-end.** После каждого голосового тикета — WS-прогон (init → user → токены → аудио → done) с замером TTFB.
- **Существующие seams.** `scripts/verify-content.mjs`, `npx tsc --noEmit`, `npm run build` — оставить зелёными.
- **Приёмка (Q11 строгая).** 16 скринов + 3 голосовых live + Firefox фолбэк + прогресс + tsc/build + смартфон через деплой + 5 одновременных сессий.

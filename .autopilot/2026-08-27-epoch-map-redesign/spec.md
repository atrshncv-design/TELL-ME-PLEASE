# Спецификация: Карта эпох по плакату клиентки

## Задача

Карта эпох (`/mission`) сейчас — скучный вертикальный список карточек. У клиентки есть
нарисованный плакат-матрица времён (3 строки × 4 колонки, 12 ячеек), и карта должна
выглядеть как этот плакат: текущие карточки эпох вставляются в его пустые ячейки.
Отдельно: на платформу нужен ненавязчивый, но видимый блок прав на материалы.

## Решение

- На ПК (экран ≥1024px) `/mission` показывает плакат: фон — SVG плаката, в каждой
  ячейке поверх — компактная живая карточка эпохи (иконка, название, тэглайн, кнопка
  «Войти →»), клик ведёт на `/epoch/<slug>`. Пройденная эпоха (все 4 сектора)
  получает зелёную галочку.
- На телефоне (<1024px) `/mission` остаётся как раньше — текущий вертикальный список
  без изменений.
- Карточка «Великий Экзамен Времен» убирается с `/mission`. Вход на экзамен — карточка
  на странице эпохи Future Perfect Continuous (последнее время): серая с подсказкой
  «Сначала пройди FPC», активная после прохождения всех секторов FPC.
- Подвал «Все права защищены…» — на лендинге и `/mission`, мелким приглушённым текстом.

## Решения по реализации

1. **Ассет плаката.** Исходник `плакат.svg` (15MB, 3401.57×1700.79 viewBox, 3 растровых
   base64-PNG: фон-градиент 3.5MB, робот 2.8MB, спутник 4.8MB). Оптимизация один раз,
   офлайн, без новых npm-зависимостей: растры вырезаются, ужимаются (`sips`, фон в JPEG,
   робот/спутник в уменьшенный PNG с альфой) и вставляются обратно; итог —
   `frontend/public/map/epoch-map.svg` ≤ 700KB. Ячеек-групп в SVG нет (один слой),
   поэтому позиционирование — по вычисленным координатам, не по id.
2. **Геометрия ячеек.** Из rect'ов SVG: ячейка ≈718.5×438.3, сетка: x₀=301.8,
   шаг 739.3 (4 колонки), y₀=254.7, шаг 460.65 (3 строки: Present/Past/Future).
   Колонки: Simple / Continuous / Perfect / Perfect Continuous. Координаты хранятся
   долями viewBox (x/3401.57, y/1700.79, w, h) — масштабируются сами на любой ширине.
   Поверх SVG — абсолютно спозиционированные HTML-слоты по этим долям.
3. **Матрица раскладки** (строка × колонка → slug эпохи):
   Present: simple→`present-simple`, cont→`present-continuous`, perfect→`present-perfect`,
   pc→`present-perfect-continuous`; Past: `past-simple`, `past-continuous`, `past-perfect`,
   `past-perfect-continuous`; Future: `future-simple`, `future-continuous`,
   `future-perfect`, `future-perfect-continuous`.
4. **Метаданные эпох** выносятся из `mission/page.tsx` в `frontend/src/lib/epochs-meta.ts`
   (slug, number, title, tagline, icon, ячейка матрицы) — источник общий для плаката и
   мобильного списка; список на мобильных не меняет разметку, только импорт.
5. **Прогресс/галочка.** Существующие чистые функции `frontend/src/lib/epoch.ts`
   (`epochProgress`, `sectorGradeKey`) — галочка, только если у эпохи пройдены ВСЕ
   4 сектора (порог подтверждён пользователем 27.08; тот же порог открывает экзамен
   на FPC). Новых хранилищ нет.
6. **Вход на экзамен (FPC).** На странице эпохи (`/epoch/[slug]`) для slug
   `future-perfect-continuous` — карточка-вход на `/exam`; активность = все 4 сектора
   FPC имеют прогресс (функция из `epoch.ts`). Серая: `opacity-60`, подсказка
   «Сначала пройди Future Perfect Continuous», клик ничего не делает.
7. **Подвал прав.** Компонент `frontend/src/components/RightsFooter.tsx` с текстом
   клиентки дословно (включая телефон, обычным текстом). Подключается на лендинге
   и `/mission`, внизу потока, `text-xs text-slate-500`.
8. **Мобильные** — без изменений поведения; брейкпоинт переключения 1024px (`lg`).
9. Деплой: статический ассет в `public/` — уезжает в тарболл автоматически; следить
   за лимитом 50MB (ассет ≤700KB не влияет).
